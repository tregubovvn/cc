# Научное описание приложения «Личный бренд преподавателя ВУЗа — ВКонтакте»

## Концепция и целевое назначение
Веб-приложение представляет собой специализированный инструмент для управления персональным брендом преподавателя вуза в социальной сети «ВКонтакте». Приложение интегрирует методы искусственного интеллекта (языковая модель DeepSeek) в процессы контент-планирования, генерации текстов и аналитики профессиональной активности. Реализовано в формате **одного HTML-файла** (`index.html`): не требует сервера, сборки и установки — достаточно открыть файл в браузере Chrome/Edge или разместить на GitHub Pages.

## Архитектурные принципы

### Автономность и локализация данных
Приложение функционирует как полностью автономное одностраничное решение (SPA). Персистентным хранилищем служит XML-файл на компьютере пользователя, что обеспечивает технологическую совместимость, долгосрочную сохранность контента, цифровой суверенитет и возможность ручного редактирования/версионирования (Git). Токены внешних API хранятся исключительно в localStorage браузера и никогда не попадают в XML-файл.

### Модульная структура
Функциональная архитектура включает три взаимосвязанных модуля, образующих замкнутый цикл контент-деятельности:
1. **Модуль планирования** — генерация структурированного контент-плана;
2. **Модуль контент-плана** — редактирование, генерация и публикация материалов;
3. **Модуль аналитики** — сбор статистики и формирование рекомендаций.

### Принцип human-in-the-loop
Языковая модель выступает когнитивным усилителем, а не автономным генератором: пользователь сохраняет полный контроль над выбором источника тем, формулированием целей, редактированием промптов и финальной редакцией текстов.

## Модуль 1: Планировщик контент-плана
Генерация плана по четырём стратегиям (общие параметры: тип плана, дата начала, периодичность, максимум постов):

1. **Извлечение из документа** — загрузка .docx/.pdf/.txt; извлечение текста через mammoth.js и pdf.js; передача в DeepSeek с системным промптом эксперта по контент-маркетингу; возврат JSON-массива {date, time, topic, format, goal}.
2. **Тематическая декомпозиция** — явный список тем с кратностью; автоматическое распределение по датам с учётом периодичности; генерация уникальных ракурсов каждой темы.
3. **Аналитическое прогнозирование** — ранжирование постов стены по ER, выявление успешных паттернов; каждый новый пост содержит ссылку `analyticsRef` на пост-источник.
4. **Пользовательские промпты** — именованные шаблоны System/User-промптов; библиотека сохраняется в XML; загрузка из .txt; выбор из списка; снимок промпта фиксируется в каждом посте; примеры: «Научные анонсы», «Методические материалы», «Студенческие достижения», «Экспертные комментарии».

## Модуль 2: Контент-план
- **Структура поста**: UUID, дата/время, тема, формат (статья, карточка, опрос, видео, сторителлинг, кейс, подборка), цель, текст, статус публикации, снимок промпта (`customPromptSnapshot`), `customPromptId`, `analyticsRef`, флаг `needsRewrite`, `originalText`, дополнительные сведения автора.
- **Редактирование**: интерактивные поля даты/времени/темы/формата/цели; ручное редактирование текста; модальный просмотр; копирование в буфер обмена.
- **Интеллектуальная генерация**: единая кнопка «🪄 Генерировать / 🔄 Перегенерировать»; кнопка «🤖 Промпт» с выбором/редактированием System и User-промптов; индикатор «🤖 свой промпт».
- **Дублирование**: «📑» создаёт копию со сдвигом +1 день и флагом «требуется переписать»; «✍ Переписать» — семантическая переформулировка через DeepSeek с требованием лексической уникальности.
- **Статус публикации**: переключатель «🔒 Publ. / ○ Publ.»; блокировка редактирования опубликованного поста (зелёная рамка, замок); снятие блокировки.
- **Публикация**: «📤 Опубликовать» активна только для постов на сегодня; метод `wall.post` через JSONP; отложенная публикация (`publish_date`); автооткрытие поста в новой вкладке.
- **Экспорт**: JSON (полные метаданные), CSV (разделитель `;`, UTF-8 с BOM для кириллицы в Excel).

## Модуль 3: Аналитика страницы
- **Способ 1 — VK API (JSONP)**: поддержка двух типов учётных данных — пользовательский токен (своя стена: извлечение владельца из ссылки id…, wall…, club…, screen-name через users.get/groups.getById, `wall.get` с filter=owner) и сервисный ключ доступа (dev.vk.com, чтение публичных стен/сообществ: запрос `wall.get` напрямую по `domain` (например, inpitsstu) или числовому `owner_id` (например, -12345678) из поля «Сообщество или ID»). Метрики likes/comments/reposts/views, расчёт ER = (Л+К+Р)/П × 100%. Публикация (`wall.post`) выполняется только пользовательским токеном; домен сообщества при этом разрешается в отрицательный ID через groups.getById.
- **Способ 2 — парсинг HTML**: многостратегийный разбор сохранённой страницы («Веб-страница полностью»): (1) извлечение JSON из `<script>`; (2) элементы `[data-post-id]`; (3) классы `.wall_item/.post/.Post/.WallPost`; (4) regex по `.wall_post_text/.pi_text`. Диагностика неудачи: размер файла, счётчики маркеров, наличие маркеров ВК, число `<script>` тегов + рекомендации.
- **Отображение**: сводные средние показатели, таблица всех постов, топ-5 по вовлечённости.
- **Аудит бренда через DeepSeek**: топ-20 постов передаются модели в роли эксперта по личному бренду; возвращается структурированный JSON-отчёт: сильные стороны, слабые места, контент-стратегия, 7 шагов на месяц, 5 идей постов; отчёт сохраняется в XML.

## Система хранения данных
**XML-файл** (сохраняется на компьютере): профиль (ФИО, должность, дата создания), библиотека пользовательских промптов, контент-план со всеми метаданными и снимками промптов, данные аналитики стены, отчёт аудита. **Не сохраняются**: токены API.
**localStorage браузера**: токен DeepSeek, пользовательский токен VK API, сервисный ключ VK, ссылка на стену, «Сообщество или ID».
**Автосохранение**: отслеживание изменений, debounce 1 с; Chrome/Edge — прямая перезапись файла через File System Access API (красная пульсирующая кнопка при несохранённых изменениях); другие браузеры — скачивание файла.

## Интеграция с внешними API
- **DeepSeek**: REST через HTTPS, модель `deepseek-chat`, temperature 0.7, max_tokens 4000, роли system/user; сценарии: план из документа/тем/аналитики/по промпту, генерация текста, переписывание, аудит.
- **VK**: JSONP (обход CORS без серверного прокси), версия 5.199, методы `wall.get`, `wall.post`, `users.get`, `groups.getById`.

## Технологический стек (в рамках одного файла)
React-подход заменен компактным нативным JS (IIFE-модуль `App`); Tailwind CSS — через CDN; mammoth.js и pdf.js — через CDN; File System Access API / File API; DOMParser и регулярные выражения; встроенный генератор UUID v4. Отсутствие сборки делает приложение пригодным для прямого размещения на GitHub Pages и локального открытия `index.html`.

## Безопасность и приватность
Никакого сервера; все данные локальны; токены изолированы в localStorage и не экспортируются; отсутствие телеметрии и внешних запросов кроме DeepSeek/VK; HTTPS из коробки на GitHub Pages; открытый проверяемый код; XML может быть зашифрован пользователем вручную.

## Заключение
Приложение сочетает принципы автономности данных, интеллектуальной поддержки контент-деятельности (human-in-the-loop) и аналитического осмысления коммуникационной эффективности. Механизм пользовательских промптов формирует основу накопления лучших практик генерации, обеспечивая стилистическую согласованность массива публикаций и воспроизводимость результатов благодаря снимкам промптов.
